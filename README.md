# Sketch map

Внутрішній вебзастосунок для польових команд: вибрати завдання, відредагувати
об'єкти на карті, зібрати аркуш формату A4 і вивантажити його як JPEG
у друкарській якості (300 dpi) з UTM-сіткою та фіксованим масштабом.

Все працює прямо в браузері, окремий сервер не потрібен. Карта й дані живуть
в організаційному ArcGIS Portal, застосунок лише показує їх і допомагає
готувати друк.

Докладні вимоги й архітектура: [PROJECT_SPEC.md](PROJECT_SPEC.md).
Історія змін: [IMPLEMENTATION_LOG.md](IMPLEMENTATION_LOG.md).

## Для кого і навіщо

- **Оператор** обирає код завдання — і бачить на карті тільки об'єкти цього
  завдання: межі, точки, свідчення (evidence).
- **Редактор** додає топографічні об'єкти (точки, лінії, полігони),
  виправляє їхню геометрію й атрибути, заповнює таблицю свідчень
  (код знака, опис, кут повороту).
- **Друк** збирає готовий аркуш: карта в заданому масштабі, координатна
  сітка, легенда, штамп з координатами ключових точок (LM/BM/SP), шапка
  з кодом завдання, масштабна лінійка, стрілка півночі, логотип.

Типовий шлях користувача: увійти через Portal → знайти код завдання →
перевірити/відредагувати об'єкти → відкрити «Макет друку» → розставити
легенду й додаткові карти → експортувати JPEG.

## Як це працює (простими словами)

1. **Вхід.** Застосунок просить увійти через організаційний Portal
   (той самий логін, що й для інших корпоративних карт). Без входу
   приватні карти й шари недоступні.
2. **Вибір завдання.** Список кодів завдань підтягується з сервісу.
   Після вибору карта фільтрується: зайве ховається, потрібне лишається,
   вигляд центрується на ділянці завдання.
3. **Редагування.** Дозволені шари редагуються прямо на карті або через
   таблицю під картою. Заборонені операції (наприклад, видалення свідчень)
   в інтерфейсі просто відсутні.
4. **Макет друку.** Окрема вкладка з аркушем A4 (книжкова або альбомна
   орієнтація). Масштаб вибирається зі списку або вводиться вручну.
   Система координат (зона UTM) визначається автоматично за ділянкою,
   сітка прив'язується до міліметрів паперу: 1 мм аркуша — один крок сітки.
5. **Експорт.** Кнопка збирає карту, сітку, підписи координат, легенду,
   штамп і оформлення в один JPEG-файл. Інтерфейс програми у файл не
   потрапляє — тільки аркуш.

## Як реалізовано

- **Платформа:** React + TypeScript + Vite, односторінковий застосунок (SPA).
  Збирається в статичні файли й публікується на GitHub Pages.
- **Карта:** ArcGIS Maps SDK for JavaScript (`@arcgis/core`). Базова карта
  й шари беруться з WebMap з Enterprise Portal.
- **Авторизація:** OAuth authorization code + PKCE через IdentityManager SDK.
  Секретів у коді немає: ідентифікатор клієнта публічний, паролі й токени
  ніде не зберігаються й не пишуться в логи.
- **Дві карти на одних даних:** вкладка «Редагування» має вільну навігацію,
  вкладка «Макет друку» — фіксований масштаб і власну систему координат.
  Дані спільні, вигляд і фільтри — незалежні.
- **Фільтрація завдань:** зв'язки між шарами йдуть через глобальні
  ідентифікатори (GlobalID). Великі списки б'ються на пакети, щоб не
  перевантажувати сервіс.
- **Умовні знаки:** живуть у файлі `public/symbols/library.json`.
  Точкові знаки — малюнки SVG, лінійні — програмно описані лінії
  (паралелі, пунктир, маркери вздовж), заливки полігонів — сітки маркерів
  з кроком у міліметрах або суцільний колір. Символіка підміняється тільки
  в браузері, опубліковані сервіси не змінюються.
- **Легенда:** власна, будується з того, що реально потрапило в рамку
  аркуша (знаки свідчень, живі знаки шарів завдання, топознаки). Віджет
  легенди Esri не використовується.
- **Додаткові міні-карти:** поверх аркуша — невеликі карти ключових точок
  (LM — завжди, BM — по одній на точку, з нумерацією як у штампі).
  Масштаб у них зафіксований, вміст можна рухати, розмір і положення —
  тягнути мишкою.
- **Сітка і підписи:** малюються поверх карти й точно обрізаються рамкою.
  Підписи координат — зовні рамки, як на паперових картах.

## Поточна конфігурація

- Portal: `https://gis.htgoims.org/portal`
- WebMap: `346b8032e4ae40e582249ba5f9dfe872`
- Шари: завдання й свідчення (читання/фільтр, свідчення — тільки правка
  атрибутів), топошари (створення/зміна/видалення за правами сервісу),
  довідковий шар статусів IMSMA (тільки читання).
- Друк: A4, масштаби 1:500–1:10000 + довільний 1:100–1:100000,
  зони UTM 35N/36N/37N (EPSG:32635/32636/32637), JPEG 300 dpi.

## Швидкий старт локально

Потрібні Node.js і доступ до організаційного Portal.

```sh
npm ci
npm run dev
```

Відкрити `http://localhost:5173/`, натиснути «Увійти через ArcGIS Portal»
і повернутися в застосунок. У налаштуваннях Portal Application вже
зареєстрований локальний redirect URI `http://localhost:5173`.

## Публікація на GitHub Pages

1. Створити GitHub-репозиторій і запушити гілку `main`.
2. У Portal Application додати точний production redirect URI вигляду
   `https://<власник>.github.io/<репозиторій>/` (зі слешем у кінці).
   Без цього вхід на опублікованому сайті не спрацює.
3. У репозиторії відкрити **Settings → Pages** і вибрати **Source:
   GitHub Actions**.
4. Workflow `.github/workflows/deploy.yml` сам збере Vite з правильним
   базовим шляхом і опублікує папку `dist`. Деплой запускається кожним
   push у `main`.

Базовий шлях для project site підставляється автоматично, правити
`vite.config.ts` вручну не треба.

## Бібліотека умовних знаків

Один запис у `public/symbols/library.json` = один знак: код (значення поля
`symbol_code`), назва, геометрія (точка/лінія/полігон), список шарів,
плюс `svg` / `stroke` / `pattern` / `outline` + `fill`. Шаблони створення,
відображення на карті, таблиця свідчень і легенда будуються з цього файла
автоматично — правити код не треба.

SVG лежать у `public/symbols/`: точкові — 48×48 з прозорим фоном.
Схема з автодоповненням: `public/symbols/library.schema.json`.

```sh
npm run symbols:check                                     # перевірка (ходить і в prebuild)
npm run symbols:import -- public/symbols/_new --geometry=point --layers=topoPoint --prefix=TOPO_
```

`import-dir` перетворює кожен `*.svg` у папці на запис (код — з імені файла,
назву дописати вручну), дублі пропускає. Імпорт тільки з-під `public/`.
Після змін у бібліотеці натиснути в застосунку **«Оновити знаки»** —
перечитує JSON/SVG без перезавантаження сторінки.

## Перевірки

```sh
npm run lint
npm run build
```

Приватні WebMap і сервіси перевіряються тільки після входу в Portal.
Якщо шар не відображається в обраній зоні UTM або поза своїм діапазоном
масштабів — застосунок покаже пояснення, а не порожню карту.

## Обмеження і безпека

- Хто що бачить і редагує — визначають Portal (доступ до елементів,
  групи) і можливості сервісів, а не кнопки в інтерфейсі. Приховування
  кнопки не замінює прав на сервері.
- Точність масштабу на папері перевіряється фізичним друком у режимі
  «100% / Actual size»: рамка карти при експорті не змінюється.
- Великі завдання й довгі списки ідентифікаторів обробляються пакетами;
  відсутність пов'язаних полігонів або точок показується повідомленням,
  а не мовчазним порожнім аркушем.
